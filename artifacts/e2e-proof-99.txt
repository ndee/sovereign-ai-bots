PART B — RULE CREATION VIA THE MATRIX BOT: NOT SUPPORTED (BLOCKER)
--------------------------------------------------------------------------------
New requirement: screenshots must show the #99 content rule being CREATED via the
Matrix bot in Element.io.

Result: the Mail Sentinel Matrix bot CANNOT create body/snippet content rules.

Live verification (operator -> alert room, app.element.io):
  Operator: "Please create a content policy: if a message body contains
             \"deadline-override-2026\", escalate it to RED."

  Bot reply (verbatim, @mail-sentinel):
    "Content policies matching message body text are not supported. The policy
     system only accepts:
       - `type`: `sender` or `domain`
       - `match`: the email address or domain pattern
       - `min-zone`: `gray`, `amber`, or `red`
     Body content matching cannot be configured via policies. The default routing
     evaluates message content automatically during scans.
     If you know the sender or domain that sends messages containing
     \"deadline-override-2026\", I can create a sender/domain policy to force those
     to RED zone. Otherwise, the content-based escalation must rely on the default
     routing logic."

Reproduced with two phrasings (natural-language and explicit "scope body");
both refused. No policy was created (policy list unchanged: 1 pre-existing sender
policy).

ROOT CAUSE (in sovereign-ai-bots, not the node-pro e2e suite):
  The Matrix bot agent's tool surface only exposes a sender/domain form of
  `policy add`. The allowedCommands whitelist in
    bots/mail-sentinel/sovereign-bot.json
  (and the generated workspace/TOOLS.md the agent reads) lists only:
    policy add --type <type> --match <pattern> --min-zone <zone> --json
  It does NOT expose --scope (body|snippet|subject), --contains, or --max-zone.
  So the agent has no way to create the #99 content-scoped rules and correctly
  reports them as unsupported. This is unchanged on bots origin/main HEAD
  (4204821) — no open PR adds scoped content-policy creation to the Matrix
  surface.

FIX NEEDED (bots side) to satisfy this requirement:
  Extend the mail-sentinel allowedCommands whitelist + TOOLS.md (and AGENTS.md
  guidance) to expose content-scoped policy creation via Matrix, e.g.:
    policy add --type content --contains <text> --scope <scope> --min-zone <zone> --json
  Once exposed, the operator can create a body/snippet rule by DM and the bot can
  confirm it, and this screenshot requirement becomes capturable.
